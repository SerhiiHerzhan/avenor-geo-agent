# Search Console: повідомлення про помилку 403

Публічна перевірка 8 жовтня 2026, 15:14 за Києвом: усі 15 сторінок Avenor повертають HTTP 200, `robots.txt` та `sitemap.xml` доступні. Сторінки збігаються з підготовленою версією, мають `index,follow` і відповідні canonical; серверного `X-Robots-Tag: noindex` немає. Загальні правила robots.txt дозволяють Googlebot.

Запит із назвою User-Agent Googlebot також отримав 200, але це не перевірка з підтвердженої IP-адреси Google. Доступу до вашого Search Console та журналів хостингу агент не має. Повідомлення 403 може стосуватися попереднього обходу; без точного URL і дати обходу це не встановлено.

## Що натиснути

1. У Search Console відкрийте точний URL зі списку сторінок із помилкою 403. Перевірте дату останнього сканування.
2. Натисніть кнопку перевірки опублікованої URL-адреси. Назва може трохи відрізнятися залежно від мови інтерфейсу.
3. Якщо поточна перевірка Google успішна й індексація дозволена, натисніть запит індексування.
4. У звіті індексування відкрийте причину 403 і запустіть перевірку виправлення.
5. У розділі файлів Sitemap подайте `https://stowarszawa.com/sitemap.xml`, якщо він ще не поданий.

Перевірка виправлення та запит індексування не гарантують включення в індекс або пошукові позиції. Звіт зміниться після наступних перевірок Google.

## Якщо поточна перевірка Google знову повертає 403

Передайте підтримці хостингу точний URL і час поточної перевірки Search Console. Попросіть знайти запит у журналах сервера, перевірити блокування справжніх Google-краулерів і назвати конкретне правило, якщо воно відхиляє запит. Не змінюйте права та правила сервера лише через старий запис у звіті: поточні публічні запити вже успішні.

Текст для підтримки за цієї умови:

> Сайт stowarszawa.com відкривається у браузері з HTTP 200, але поточна перевірка URL у Google Search Console для [точний URL] о [час] повертає 403. Прошу знайти відповідний запит Google у журналах та перевірити конкретне правило доступу/антибота. Назви User-Agent недостатньо для перевірки походження; використайте офіційний спосіб перевірки Google IP. Потрібен доступ підтвердженого краулера до публічних сторінок і sitemap.

## Інше спостереження

HTTP та www-варіанти головної також відповідають 200 без перенаправлення на HTTPS без www, хоча canonical правильний. Це окрема можливість узгодити адреси на хостингу; не встановлена причина попереднього 403.
